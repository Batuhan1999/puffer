# Grounding: agent bridge and system access

Phase A artifact for `architect`. The parent built or reviewed every module below in this session. Facts are labeled verified (observed in code or on the simulator), read (from a source), or belief (unverified).

## The task

Two features for the Puffer iOS prototype:

1. **Agent bridge.** Personal agents (Claude, ChatGPT, Poke, and similar) ask Puffer questions. The phone answers from its on-device index after the user approves each request, or without asking for collections the user pre-approved for that agent. Only captions, text snippets and explicitly approved images leave the phone. Never the index, never vectors.
2. **System access.** Siri, Shortcuts and Spotlight can use Puffer: "search Puffer for the lease deposit" in Siri or Shortcuts, Puffer items findable in Spotlight, results usable by other apps through App Intents.

## Current system (verified)

- Expo SDK 55, React Native 0.83.10, React 19.2, Expo Router (routes in `src/app/`), iOS only, deployment target 18.0. Built with `npx expo run:ios` against Xcode 26.3; `ios/` is generated by prebuild (Continuous Native Generation), never edited by hand. Simulator iPhone 17 Pro, iOS 26.3.1.
- Native module `modules/gemma-embed/` (Swift, Expo Modules API, pod `GemmaEmbed`, `static_framework`). Wraps LiteRT-LM v0.18.0 `EmbeddingEngine` (vendored `CLiteRTLM.xcframework` plus Swift sources) and a folder store (security-scoped bookmarks in UserDefaults, recursive scan, coordinated reads, PDFKit text). JS API: `load`, `embedTexts`, `embedImage`, `pdfText`, `pickFolder`, `listFolders`, `scanFolder`, `readFolderText`, `copyFolderFile`. The model file (388 MB `.litertlm`) lives in the app's Documents directory. Load takes about 1.2 s on the simulator CPU.
- Index and search live in JavaScript:
  - `src/library.ts` persists items in expo-sqlite (`puffer.db`, table `items(id, kind, title, text, sourceUri, thumbName, addedAt, vec BLOB 768xfloat32)`) and loads all rows into memory at startup.
  - `src/puffer.ts` holds the in-memory `Puffer` index: a `Float32Array` N x 768 segment, MRL-truncated cached views, brute-force dot-product scan, BM25 over passage text, hybrid = 768d similarity + 0.1 x normalized BM25, relative cutoff (top similarity minus 0.1, at least 3 hits).
  - `src/model.ts` embeds queries with the prefix `task: search result | query: {q}` and passages as `title: {t} | text: {c}`.
- `src/store.tsx`: `PufferProvider`, `usePuffer()`, `useSearch()` is the single data contract for all screens.
- `src/ui/preview.tsx`: in-memory reducer for the agent preview: `Collection` (saved description query, hidden item ids), `Agent` (allowed collection ids), `AgentRequest` with `RequestStatus` union `pending | shared{itemIds, at} | denied{at}`, search prefs, recents, timings. Resets on relaunch. Requests are simulated on the phone.
- Routes: `src/app/(tabs)/agents/index.tsx` (requests, agents, collections access, history), `src/app/request/[id].tsx` (review modal: runs a real local search for the question, per-item toggles, photos off by default, "Approve and Share N Snippets", Deny).
- The JS runtime is only alive while the app runs. All search today needs it.

## Platform constraints

- MCP (read, modelcontextprotocol.io 2025-11-25): remote servers speak Streamable HTTP; OAuth 2.1 resource server with RFC 9728 metadata, PKCE, RFC 8707 audience; clients may also use static bearer keys. Tools may declare async task support for long-running calls.
- Claude.ai and ChatGPT connectors call remote MCP servers from the vendor's cloud, so the server must be publicly reachable over HTTPS (read). Poke accepts a URL plus API key or OAuth, and `npx poke tunnel` exposes local servers (read). Claude Code on this Mac can use a local MCP server over stdio or http://localhost (verified available as a test client).
- No agent can reach a server that runs on the phone itself (read). A relay is required for remote agents.
- iOS background: a suspended app keeps no sockets. Silent push is throttled (about 2 to 3 per hour) and gives about 30 s (read). Push Notifications need a paid Apple Developer account; a free personal team cannot use the push capability (read: Apple Developer Forums, https://developer.apple.com/forums/thread/768748, citing Apple's supported-capabilities table). The user currently has only a free Apple ID in prospect.
- App Store guideline 5.1.2(i) requires disclosure and explicit permission before sharing personal data with third-party AI (read).
- Embedding vectors are invertible (Vec2Text recovered 92% of 32-token inputs) (read). Never send vectors.
- App Intents (iOS 18+): `AppIntent`, `AppEntity`, `EntityQuery`/`EntityStringQuery`, `IndexedEntity` for Spotlight and Apple Intelligence, `AppShortcutsProvider` for zero-setup Siri phrases (read). Intents can run in the app process without opening UI. App Intents metadata is extracted at build time from the target that declares them; whether a CocoaPods `static_framework` pod qualifies is unverified (belief: it may not, and intents may need to live in the app target via a config plugin or in an App Intents extension).
- Expo prebuild regenerates `ios/`, so any app-target Swift file or entitlement must come from `app.json` or a config plugin.

## What the parent can verify here

- Simulator end to end: the app, a relay running on this Mac (reachable from the simulator at localhost), and a test agent (Claude Code via a local MCP config, or curl/`@modelcontextprotocol/inspector` CLI against Streamable HTTP).
- Siri and Shortcuts on the simulator: the Shortcuts app and App Shortcuts can be exercised; Spotlight indexing can be checked with Spotlight search.
- Not here: a public HTTPS endpoint (deploying or tunneling exposes personal data externally; it needs the user's explicit go-ahead), a real iPhone, push notifications.

## Non-goals for this round

- No production auth provider, no multi-user relay, no App Store submission.
- No new embedding model or search algorithm work.
