# Candidate c: one native core, a mailbox relay, a type-guarded egress

## Problem

Two features need the same thing: answer a question from the on-device index without the React Native runtime in the loop. Siri and Shortcuts cold-start the app process for an App Intent, with no JS. An agent request that a user pre-approved should not need a screen. Today the index (`src/puffer.ts`), the SQLite rows (`src/library.ts`) and the consent state (`src/ui/preview.tsx`) all live in JS, so none of that works when JS is not alive, and two copies of search would split ownership.

Constraints from grounding that shape the design. Agents cannot reach a phone, so a relay is required. A suspended iOS app has no sockets. Push needs a paid account the user may not have. Vectors are invertible and never leave. App Intents metadata comes from the declaring target, and `ios/` is regenerated by prebuild. The demo must run on this Mac with no public endpoint.

## Usage (caller's view)

**Demo, end to end on this Mac.**

```
$ pnpm tsx relay/main.ts
relay listening on 127.0.0.1:8787
pairing code 482913 (10 min)
```

In the simulator, Agents tab, Connect Relay: enter `ws://localhost:8787` and `482913`. Then Add Agent "Claude Code". The app shows the credential once:

```
claude mcp add --transport http puffer http://localhost:8787/mcp \
  --header "Authorization: Bearer pk_a7f3....secret"
```

(Syntax checked against Claude Code's MCP docs.) In Claude Code: "ask puffer for my lease deposit". The agent calls `search({query: "lease deposit"})`. The phone shows a review. The user approves two snippets. The agent receives:

```json
{ "status": "answered", "via": "user", "photosWithheld": 0,
  "items": [{ "ref": "1", "kind": "passage", "title": "Lease.pdf p2", "snippet": "The deposit is ..." }] }
```

If the user is slow, the call returns `{status:"pending_user", requestId}` after 45 s and the agent calls `check_request({requestId})`. If the phone is backgrounded, the answer is `phone_offline` with a requestId, and the request waits in the relay for up to 10 minutes.

Grant Claude Code the Receipts collection in the Agents tab. Now `search({query:"coffee grinder receipt"})` answers at once, text only, from Receipts members only, and the History row says "Answered automatically". A photo in that collection is not sent. The result says `photosWithheld: 1` and the agent may call `search({query, broaden:true})`, which opens a review.

**Siri, Shortcuts, Spotlight.** "Search Puffer" in Siri asks what to look for, then speaks the top hit. In Shortcuts the action "Search Puffer" takes text and returns `[PufferEntity]` for the next action. Spotlight shows Puffer items after the user turns on "Show in Spotlight". Tapping one opens `puffer://item/<id>`.

## Shape

**One engine, in Swift.** `PufferIndex` (actor, `Index.swift` plus pure `Ranking.swift`) is the only search implementation. It ports `puffer.ts` (matrix scan via Accelerate, BM25, hybrid fusion, relative cutoff) and owns the SQLite store (`Store.swift` opens the same `puffer.db`, so existing libraries survive). JS, the relay session and App Intents all hit `PufferIndex.shared`. `puffer.ts` is deleted in the same change, and `library.ts` shrinks to a facade with the surface `ingest.ts` already uses. Search returns ids and scores only, so no text or vector crosses to JS during a query. Parity is pinned by golden fixtures generated from `puffer.ts` before deletion, per build-the-lever and migrate-callers-then-delete.

**Native owns consent state, because native enforces it.** Collections, agents, grants and the request ledger move from the `preview.tsx` reducer into the same database and into Swift. `useBridge()` is a read model: subscribe to one `changed` event, refetch `snapshot()`. `usePreview` keeps prefs, recents and timings. One owner per state, per the separate-before-serializing and single-source rules.

**Consent is a type, not a convention.** `Consent.swift` declares `Approval` with a `fileprivate init`. `Egress.materialize` accepts only an `Approval` and reads text and thumbnails from the index at send time. An `Approval` is produced two ways: `Policy` proves a request is covered by grants (auto), or `userApproved` receives ids and checks each is inside the proposal `offered` set stored when the request arrived. Code outside that file cannot build one. JS cannot widen a share: it sends ids, never content, and ids outside `offered` throw `notOffered`. Per encode-lessons-in-structure and boundary-discipline.

**Grants scope the search, they do not filter after it.** Collection membership is defined once, in `PufferIndex.members(of:)` (query hits above the cutoff, minus hidden). A granted ask runs with a row mask of the allowed members, so rows outside the grant are never scored, and the answer is text snippets only. An agent with no grants, a `broaden` ask, or one over 30 auto answers a minute gets the review path over the whole index. Photos are never auto: image bytes leave only through a review where the user switched that photo on. `Policy.swift` is pure, with no I/O.

**The relay is a mailbox with no data and little trust.** `Mailbox` (`relay/mailbox.ts`) is a state machine: `queued, delivered, answered, expired`, idempotent on `requestId`, first answer wins, results deleted on collection or TTL. It holds no index, no cache, no collection names. It keeps one durable file: the paired device key and agent credential hashes. The phone dials out (WebSocket), so no inbound path to the phone exists. Frames are parsed once at the socket (`protocol.ts`, mirrored by `Wire.swift`; golden JSON files in `contract/` are decoded by both test suites). The relay terminates TLS, so it can read queries and snippets in transit. That cannot be avoided for Claude.ai or ChatGPT connectors, and the design says so rather than claiming end-to-end privacy.

**Agent authentication.** The phone mints the credential (`pk_<agentId>.<secret>`), shows it once, and sends only `sha256(secret)` to the relay in a frame signed with the device key. The phone's own agent table is authoritative for names, grants and revocation, so a relay that invents an agent id gets dropped by the phone. A compromised relay can still replay a known agent id, which is the honest limit. `AgentAuthenticator` is the seam where OAuth 2.1 (RFC 9728, PKCE, RFC 8707) replaces the bearer check for hosted connectors, with no other change. The device authenticates by P-256 challenge-response (Secure Enclave on hardware, software key on the simulator).

**Agent surface is two tools.** `search(query, broaden?)` and `check_request(requestId)`, on Streamable HTTP via the official SDK. MCP tasks are experimental in 2025-11-25 and need client opt-in, so polling by tool works with every client today. Wait is 45 s, under Claude Code's 60 s first-byte timer (checked in its docs), kept alive with progress notifications.

**App Intents.** `SearchPufferIntent` (free text in, `[PufferEntity]` out, for Shortcuts), `OpenPufferItemIntent` plus `PufferEntityQuery: EntityStringQuery` (the spoken path), `AppShortcutsProvider`. Authentication policy is `.requiresLocalDeviceAuthentication` (case verified in Apple docs), so Siri on a locked phone asks for unlock before touching the library. Intents run in the app process and cold-start without RN. Text search uses a 2 s embed deadline; past it, it degrades to BM25 so Siri never hangs on the 388 MB model. Spotlight is a derived mirror (`SpotlightMirror.reconcile` diffs by revision), opt-in, deleted when switched off. It is derived, not synced.

**Expo build.** Native code lives in two pods: the existing `GemmaEmbed` (engine, folders, PDF), and a new local module `puffer-core` (index, store, policy, consent, bridge, intents source). `GemmaEmbed`'s `EmbedRuntime` becomes public, persists the last model path, and gains `ensureLoaded()` so a cold intent can load the model itself. The intents file is the only code that must live in the app target (metadata extraction is per declaring target; static pod qualification is unverified). A config plugin copies `app-intents/PufferIntents.swift` into `ios/<App>/` and registers it with `IOSConfig.XcodeUtils.addBuildSourceFileToGroup` (exists in the installed `@expo/config-plugins`), plus `NSAllowsLocalNetworking` for `ws://localhost`. Nothing in `ios/` is hand-edited. `AppIntentsPackage` (iOS 17+, verified) can later shrink the plugin to a three-line file if a spike shows the pod qualifies.

**Locked phone and suspended app, honestly.**

| State | Result |
| --- | --- |
| App foreground, unlocked | Socket up. Auto answers instant. Reviews appear in the Agents tab. |
| Backgrounded or locked | Socket dies within seconds. Relay marks offline. Agents see `phone_offline`; the request waits up to 10 min. A short background task finishes an answer already in flight. |
| App opened again | Connect, `sync`, relay re-sends unanswered asks, ledger re-sends answers. All idempotent. |
| Pre-approved ask while suspended | Not answered. Pre-approval removes the prompt, not the need for a running app. Silent push could give about 30 s, throttled to 2 to 3 an hour, and needs a paid account. `Bridge.wake()` is the reserved entry point. Not in the prototype and not demoable here. |
| Siri on a locked phone | Prompts for unlock, then runs in the app process. Library files use `CompleteUntilFirstUserAuthentication`. |

The relay never caches snippets to fake availability. A standing copy of the user's text on a server would break the premise.

Interface depth. The JS surface of the engine is `search`, `addItem`, `snapshot` and a handful of actions, hiding ranking, storage, scoping, consent, the socket and Spotlight. The relay's public face is two tools and one socket. App Intents are one-line forwards into `SystemSearch`.

## Tradeoffs accepted

- We accept porting ~250 lines of ranking to Swift in exchange for one engine that works with no JS and no duplicate. The cost is a risk of drift from `puffer.ts` until fixtures pass.
- We accept moving consent state out of the React reducer in exchange for enforcement that works headless and a compiler-checked egress.
- We accept a relay that sees plaintext in transit in exchange for working with Claude.ai and ChatGPT connectors.
- We accept no answer while the phone is suspended in exchange for never storing user content on a server. Push is deferred.
- We accept two tools plus polling over MCP tasks in exchange for client compatibility.
- We accept two wire implementations (TS and Swift) with golden files in exchange for the bridge running when JS is dead.
- We accept photos never being auto-shared in exchange for a simple rule on the riskiest data.
- We accept one phone per relay.

## Alternatives considered

- **Bridge client in JS, search stays in JS, intents duplicate search in Swift.** Rejected: two search implementations with hand-synced scoring, and a consent invariant that JS cannot hold in a type. Shallow: callers coordinate two engines.
- **App Intents extension plus App Group shared database.** Rejected: separate process cannot load the 388 MB model in extension memory limits, and a second reader of the store splits ownership. The in-process intent needs no group.
- **Relay holds an encrypted or plain cache of granted collections to answer while the phone sleeps.** Rejected: a standing server copy of personal text. Not the premise.
- **Relay-side consent (relay knows grants, enforces them).** Rejected: the relay does not hold the data or the truth about grants, and would become the thing to trust.
- **Agents talk to the phone directly (local server on device).** Impossible: no agent can reach it, and iOS suspends listeners.

## Open questions and risks

1. Does moving SQLite ownership to Swift beside an existing expo-sqlite file migrate cleanly (WAL files, the `SQLite/` directory)? Should the spike open the file read-only first?
2. Are App Shortcut phrases limited to entity and enum tokens, so "search Puffer for X" must go through `EntityStringQuery`? Is that natural enough in Siri on iOS 26? (Belief, not verified; Apple pages were not fetchable.)
3. Does the intent source need to sit in the app target, or does a static pod with `AppIntentsPackage` extract? The spike builds both and checks the generated `Metadata.appintents`.
4. Cold intent latency: model load plus index load on a device, not the simulator. Is a 2 s deadline right? Should keyword fallback say it degraded?
5. Wire drift between Swift and TS. Are golden files enough, or should one schema generate both?
6. Is the 10-minute TTL right when an old request surfaces after the user returns? Should the review screen show age prominently?
7. Should approving a photo require Face ID?
8. Spotlight exposes snippets on a locked phone's search. Is opt-in per kind (photos vs text) needed?
